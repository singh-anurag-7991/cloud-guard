Cloud Guard

Finds the AWS spend you forgot about — and hands you the command that stops it.

● Live — running now

The problem

Cloud waste is rarely dramatic. It is a 500 GiB volume left behind when someone terminated an instance. An Elastic IP nobody released. Snapshots a backup script created in 2024 and never cleaned up.

Individually invisible on a bill. Together, real money every month — forever, because nothing in AWS will ever tell you to delete them.

How it works

  1. Launch the CloudFormation template Creates a read-only role in your account. No access keys are ever shared with us.
  2. Paste the role ARN back We validate it by actually assuming the role, so a wrong ARN fails immediately instead of silently returning nothing.
  3. Scan every enabled region EC2, EBS, Elastic IPs, snapshots, RDS, S3 and Cost Explorer. Five regions at a time, so AWS does not throttle you.
  4. Rules price each finding Each attaches a dollar figure from published AWS list prices, the observation that triggered it, and a confidence level.
  5. Act, or export Copy the exact AWS CLI command from the dashboard, or pull the whole list as CSV to send to your team.

What it checks

Unattached EBS volume State is available — attached to no instance, still billed every hour. High confidence
Unassociated Elastic IP AWS charges $0.005/hour precisely because it is idle. Free once attached. High confidence
gp2 → gp3 migration gp3 costs 20% less per GiB and includes 3000 IOPS free. Online change, no downtime. High confidence
Stale snapshot Older than 90 days. The fix command checks for a backing AMI first. Check first
Idle EC2 instance Running, but under 5% max CPU across seven days of CloudWatch data. Check first
Stopped EC2 instance Not billed for compute, but its root volume still is. Check first
Public S3 bucket Public access block missing or policy grants public read. Check first
Over-provisioned RDS Instance class larger than the observed workload needs. Check first
Cost summary Week-over-week spend by service, from Cost Explorer. Reported

Why confidence levels

An unattached volume is provably serving nothing — that is high confidence, act on it. A 90-day-old snapshot might back an AMI or satisfy a retention policy — that is check first, and the fix command runs the AMI lookup before the delete.

The distinction exists because being wrong confidently costs far more trust than being cautious. A tool that once told you to delete something you needed never gets used again.

What it does not do yet: savings are estimated from on-demand list prices. Savings Plans, Reserved Instances and volume discounts are not modelled, so your real saving may be lower. That caveat sits next to every figure inside the product too.
